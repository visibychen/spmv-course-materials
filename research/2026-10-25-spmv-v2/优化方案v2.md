# 优化方案 v2：直接 CSR、低准备成本与针对性分区

日期：2026-10-25。状态：**设计稿，待审核后实现**。依据分为 v1 本机证据和一手文献 / 固定源码，编号见 [来源索引](资料与复用索引.md)。

## 1. 目标与路线

v2 的主目标仍是：在原超大均匀矩阵、R=9 下，**准备+执行优于同批重测的原始最佳线程配置**。同时修复小矩阵过度并行、集中长尾和巨行上的明显缺陷。若只改善某些不规则输入，应按输入范围交付，不能宣称主目标也达成。

推荐主线：**保留原 CSR，用轻量元数据和不同执行策略解决不同问题，避免为短任务复制约 738 MiB 的 SELL 数据。** 延续 f32/f32/f32、非转置和 y+=Ax；其他类型 / 模式沿原始分派。SELL 保留为显式候选及长复用研究路径。

| 优先级 | 改动 | 针对的 v1 缺陷 | 不能承诺的事 |
| --- | --- | --- | --- |
| P0 | 加强对照与分阶段计时 | 相同 CSR 路径的进程中位数差约 15.57% | 不能把所有差异归到包装函数 |
| P1a | 小工作量走真正串行路径 | 2048 nnz 用 24 线程慢约 249 倍 | 阈值不能直接照搬到其他机器 |
| P1b | 固定短行 CSR 展开；有限预取对照 | 均匀短行转换不回本、随机 x 访问 | 不能保证突破 24 线程原始性能 |
| P2 | 按 nnz+rows 划连续行区间 | 集中长尾按行数分配极不均衡 | 不能拆开一条巨行 |
| P3 | 适配作者 CPU merge-based 方法 | 巨行只能占用一个线程、SELL 过量填充 | 不保证对均匀输入更快或逐位相同 |
| 条件扩展 | 按调用次数核算 SELL；并行准备等消融 | 重准备、大复制、全局掩码标志 | 不是 v2 首轮必须继续扩大的路线 |

## 2. P0：先让性能差异能够归因

保留两个层面的对照：

1. **工程对照**：原始 `9352c86` 独立程序、v1 固定提交和 v2，匹配输入、线程位置、数值设置、R；用独立进程测准备+执行和全程 wall。原始程序不插入单方预热，不改写旧结果。
2. **内核对照**：同一个诊断二进制中调用同一份 original CSR、v1 和 v2 路径，采用相同的计时、y 初始化和缓存准备方式。它帮助隔离格式 / 内核，不能替代上面的真实程序总成本。

主条件安排至少 10 组相邻的原始 / 候选进程对，顺序随机为 AB 或 BA，避免总把一方放在更冷或更热的时间段。进程内稳态诊断可统一预热，但与原始程序首次调用结果分表；不能混用。保存每组顺序、实际线程数、完整范围和配对比值。若系统波动仍盖过收益，就保留不确定结论。

P 拆为 validation、row_stats、partition/team_setup、allocation、conversion、tuning。计时只能围住这些完整阶段，不在逐非零元循环中调用时钟。增加每线程 nnz / 行数的诊断输出；线程耗时诊断在独立运行收集，避免污染正式样本。

如可用，再分别做 STREAM 流式参考与内核符号的 perf 采样 [R9]。WSL 若不能提供 DRAM 控制器计数，明确缺失；cache-miss 采样和逻辑字节数不等于 DRAM 流量，STREAM 也不代表随机 gather 应达到的速度。

## 3. P1a：小矩阵先决定是否值得创建并行工作

依据 v1 小矩阵的巨大线程负收益及 OpenMP 同步 / 等待语义 [R6]，增加真正的串行执行入口，直接调用普通行区间函数，避免为小工作量进入团队和逐次屏障。

优先看已知的行数、nnz、请求线程数和 R；阈值在独立校准集上选择并冻结，再到保留集验证。不给出未经实测的“nnz<某常数永远串行”。`--execution=serial|parallel|auto` 应允许强制复现，报告实际使用线程数。

串行回退保留 y+=Ax、每行求和后加旧 y 和真实重复次数。R=0 才是无调用；对 nnz=0、R>0 的通用接口，不应盲目直接 return：y+=+0 对 -0 和非有限值的可观察行为可能与完全不写 y 不同。nnz=0 且正 --flops 继续清楚报错。

不把“把创建线程移到重复循环外”当作新增贡献——原始程序已经这样组织。默认保留通用每次调用结束的同步；不以 nowait、缓存 Ax 或把 R 次加法替换成 R*Ax 来获得本轮成绩。

## 4. P1b：超大均匀矩阵优先试不转换的短行 CSR

### 4.1 有依据的候选，不预设它胜出

参考原作者 `ellgemv16sd` 的固定宽度展开思想 [R4]，在**已证实所有行长度为 8**时直接读取原 CSR：第 i 行偏移为 8*i，无需生成 SELL 或复制值 / 列号。可省去热循环中的行界限判断；是否减少实际流量 / 指令必须看最终汇编和计数。

首轮只做一个 L=8 原型，尾部的行分组和 64 位偏移必须检查；不立即生成几十种长度内核。这里复用的是固定宽度展开方法，不把作者 double、行优先 ELL、附加对角项和 y 更新表达式原样搬来。新实现每行 sum 从零开始，最后执行一次 y[i]+=sum。

无序 / 重复列、显式零保持原 CSR 顺序。固定宽度未被完整确认时回到通用 CSR，不能根据少量抽样就假设 1200 万行均为 8 项。确认可与本来必须进行的行指针检查合并，成本记入 P。

对“交错 2/4 行以重叠加载”仅作为后续小规模消融 [R1]。文献明确指出，其软件流水线在当时乱序 superscalar 上收益有限；本机也是乱序处理器，因此它不是已证明的主收益。GCC 可能已做等价展开，新源码不同并不保证机器码更好。

### 4.2 针对 x 间接访问的有限预取

参考间接预取研究 [R2] 和 GCC 的合法地址要求 [R5]，比较 D=0 / 32 / 128 个非零元的有限候选；这些是本项目试验点，不是论文最优参数。D=0 为必要对照。

地址沿当前线程拥有的 CSR 非零元区间向前看，检查 `D < end-k` 后才读取 `column_indices[k+D]`，再请求对应 x。不能把预取限制在仅 8 项的一行内，否则 D≥8 的候选可能全部被关掉；也不能越过数组边界读取索引。若测试两级预取，再分别控制索引流和 x 请求，不盲目照抄某个固定倍数。

预取可能增加指令、TLB 压力和无效流量，尤其可能在 24 线程或热 x 上变慢。先显式选择并单独测；R=9 的生产调用不做昂贵在线穷举。所有在线试算、scratch y、恢复和参数选择若后来加入，都计入 P。若无稳定总成本收益，D=0 保持默认。

## 5. P2：连续行工作量分区，保留 CSR 与行内顺序

参考原作者显式 startrows/endrows 接口 [R4] 和 SpMV 非零元分区依据 [R1]，计算每个实际线程的连续行区间。首轮成本近似为：

```text
F(i) = row_ptr[i] + λ*i，初试 λ=1
把 F(m) 分为 T 份，在单调 F 中二分查找各线程行边界
每条完整行仍由一个线程从头到尾计算
```

不创建长度 m 的额外前缀数组；利用原 row_ptr 二分，边界元数据 O(T)，边界查询 O(T log m)。合法性与行统计若需要完整扫描，另计 O(m) 成本，不能把整个 prepare 也写成 O(T log m)。λ=1 是工程近似，不是完整 merge-path，也没有最优保证。

模型中，集中长尾的 24 线程最大 / 平均 nnz 从约 17.521 降到 1.073；这只是结构证据，不能写成“加速 16 倍”。均匀大矩阵、分散长尾、均匀分布的 99% 空行本来就接近均衡，默认不为它们强行重分区。

线程数必须绑定实际团队；避免嵌套 parallel。分界目标用商和余数构造，检查 m+nnz、乘法和 64 位范围。重复边界允许空线程，但全行覆盖必须恰好一次。保留 rows 对照，并在独立实验比较 dynamic/guided；它们是调度对照，不假定开销更低。`OMP_SCHEDULE` 不会改变没有使用 schedule(runtime) 的原循环 [R6]。

一条巨行的工作量下界仍然存在。不能在发现最长行超过每线程理想份额后，把“切换 dynamic”当作完成了巨行并行化。

## 6. P3：直接适配 merge-spmv 的 CPU 方法

采用 Merrill / Garland 的逻辑合并划分，直接处理 CSR 行结束位置与非零元序号，用 merge-path 搜索分配“行事件+非零元事件” [R3]。具体参考固定版本 CPU `MergePathSearch` 与 `OmpMergeCsrmv`，不移植整个含 MKL 的旧 benchmark。

### 本项目必须做的适配

- f32 值、int32 列号、int64 CSR 偏移；坐标、总事件数、对角线和中间表达式一并审计，不能照搬 int2 / int。
- 用实际 T 分配 scratch，不使用作者例子的固定 256 项。可缓存结构和 T 不变时的边界坐标；这属于本项目额外准备，应计时。
- 原 CPU 示例覆盖写 y；本项目要累加。完整且未拆分的行直接 `y+=sum`；跨分区行的所有片段先存入记录，不抢写 y。同步后按原片段顺序合并，再对该行加旧 y 一次。
- 每个连续区间至多有起始 / 结束两个边界片段，可用 O(T) 片段存储，处理“起始和结束在同一巨行”的去重；无需 O(m) 的整份 Ax 临时向量。这个 scratch / 延迟写回设计是本项目适配，不是作者原函数的逐行照抄。
- 每次重置片段状态，执行必须完成的计算后屏障、合并和调用完成屏障。所有线程一致进入同一路径；团队变化时重绑或一致回退，不能部分线程提前退出。
- merge 改变长行求和分组，只在允许误差界的模式启用；需要匹配行序逐位行为时走不拆行路径。片段合并的额外算术计入耗时，逻辑 FLOP/s 仍要标明按原 2*nnz 口径统计。

主测试是单条巨行跨 2/12/24 线程、集中长尾和空行边界。对均匀短行不强推 merge；99% 空行例本身 nnz 已均衡，也不因“空行多”自动选择它。

## 7. 计划、验证和调用次数必须成为显式成本

保存结构统计、所选策略、实际 T、数值模式和准备字节数；原 CSR 为规范表示。公共入口仍检查尺寸 / 类型。对不可信 CSR 保留完整验证；只有已验证且版本未失效的受控句柄才复用验证结果，指针相同不代表内容没变。

建议分开记录 structure_version 与 values_version：结构变化失效行统计、分区和 SELL；仅数值变化时直接 CSR 读新值，但 SELL 必须刷新快照。初版若没有可靠版本管理，就要求显式重建，不推测有效性。

参考 AOCL 的 expected-calls 与 memory-hint 设计 [R7]，先接收调用次数预期，不移植其整套 optimize 依赖。CLI 的实际次数还受 --flops 影响：f32 下由 repeat 与向上取整的 min_flops/(2*nnz) 共同决定，检查零元、计数溢出和循环变量范围。

```text
选择依据 = 已知规模/结构 + 实际线程 + 数值要求 + 预计调用次数
总成本 = 新增验证/构造工作 + 分析/分区/调参/转换 + R*执行 + 清理
```

把检查合并到 CSR 创建可以减少额外遍历，但新增成本仍进入工程总时间，不能通过移动计时边界让它“消失”。prepare+execute 模型外的清理另列，进程 wall 包含全过程。

首版保留显式后端；自动策略只使用独立校准并在保留集验证过的规则。未知输入 / 线程 / 调用次数默认走低准备 CSR，允许强制覆盖。不在线免费跑遍所有内核，也不把事后最小中位数当作实际自动算法成绩。若试算需额外 y，必须隔离、恢复并计时计内存，不能污染正式 y+=Ax 次数。

## 8. SELL 的条件扩展，而不是 v2 默认主线

仅在有复用证据时继续 [R8]：

1. 将验证 / 宽度统计尽可能合并；统计、64 位前缀、内存分配和转换分别计时。
2. 按 slice 并行填充互不重叠区域；前缀及总槽数的溢出检查、安全同步和失败回退不能省略。暂存宽度、对齐和旧新数组共存计入峰值预算。
3. 对全有效主体和尾块分开处理，或保存每 slice 的有效信息，避免一个尾块让全矩阵都做掩码；保留 NaN/Inf 填充安全性。对齐作为单独消融，不宣称更宽 / 更齐就必然更快。
4. 如使用代价模型，必须在转换前用已有校准估算收益；未知或误差范围覆盖收益时不转。不能先付全部转换费，再声称策略避开了转换费。

当前 24 线程、R=9 需要把准备从约 398 ms 压到约 20.6 ms 以下（约 19.3 倍），或让内核大幅更快，才可能回本。单线程 R=9 的 SELL 已有总成本优势，所以也不能简单用“R≤9 一律禁 SELL”代替按线程和成本判断。

局部排序、CSR5、压缩索引、重排、BSR 不并入首轮 v2。它们要额外结构、精度或转换适配，目前不足以优先于上述可直接解决的缺陷。

## 9. 接口与实现拆分建议

在保留 v1 核心 / 测试的后续独立 v2 分支上拆分：

| 模块 | 职责 |
| --- | --- |
| plan / stats | 已验证句柄、行统计、策略 / 线程绑定、完整成本记录 |
| csr-short | 固定 8 项短行原型，先保持行内顺序 |
| csr-prefetch | 有边界的有限前瞻；D=0 对照 |
| row-partition | rows / work 两种区间方案，O(T) 元数据 |
| csr-merge | 固定来源适配、64 位坐标、片段合并与调用同步 |
| driver | 真正串行入口、保留并行区复用、实际策略 / 线程输出 |

内核、分区、执行方式应尽量正交：例如 kernel=csr-short、partition=work、execution=parallel；merge 自带分区，非法组合清楚报错。任何固定阈值、候选距离或自动规则均标为本机校准值。

实施顺序为 P0 → P1a/P1b → P2 → P3。每项单独测试 / 消融后再组合，某项不成立就不进入默认策略。核心原始 master 不承载试验改动，本轮不创建或提交 v2 代码分支。

## 10. 验收与停止条件

具体矩阵与边界见 [验证计划](验证计划.md)。主线必须同时比较原始最佳配置、同线程原始和最强匹配 CSR 对照；不以 1→24 的原有线程扩展作为新增贡献。

本课设拟采用的保守准入标准是：目标条件的准备+执行中位数至少改善 5%，配对区间支持收益，且保留集无未解释的严重退化；5% 是工程门槛，不是论文定理。若差异被波动覆盖，增加样本或判为不确定。

不能承诺这些方法一定让超大均匀矩阵的 24 线程更快：它已经均衡，若主要限制确为共享访存资源，则分区和多加 SIMD 都不能凭空提高资源上限。若 P1 没有总成本收益，明确保留原始该路径；P2/P3 的成功只按集中长尾 / 巨行范围报告。v2 可作为有适用范围的优化交付，不能伪装成所有输入的统一胜者。
