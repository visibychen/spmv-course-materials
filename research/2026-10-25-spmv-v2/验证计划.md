# v2 实现后的验证与消融计划

本文件是计划，不是完成证明。当前新增的 JSON / CSV 只复算 v1，未运行 v2 内核。

## 1. 每项改动对应一个可检验问题

| 改动 | 必须保留的对照 | 测量重点 | 不成立时 |
| --- | --- | --- | --- |
| 新 driver / plan | v1 original、原始独立程序 | 同一算法是否仍有明显不一致；团队 / 包装 / 初始化耗时 | 先修对照，暂停宣称小幅提升 |
| 串行路径与线程选择 | 原始 1 线程、原始 12/24、强制串行 / 并行 | 全部 P、进入团队、每次调用和真实线程数 | 默认规则回到已验证行为 |
| CSR-short8 | original、scalar、pack、SELL8/16 | 是否消除循环 / 行指针读取；总成本是否胜过最强 CSR | 不把源码展开本身当成果 |
| 前瞻预取 | 同一内核 D=0，D=32/128；同样 ISA / FP | 随机 / 带状 / 热 x，1/12/24 线程，指令与缓存行为 | 删除无稳定收益的距离，不扩大无界搜索 |
| 工作量分区 | 同一内核 rows/work；独立 dynamic/guided | 每线程行数 / nnz / 时间、分区 P、集中与分散长尾 | 均匀输入保留 rows |
| merge | original、pack、work 分区 | 巨行真实跨线程、合并开销、数值误差与总成本 | 普通行或严格顺序要求时回退 |
| 可选 SELL 改进 | 固定 v1；每次只改并行准备、掩码或对齐之一 | P 分项、复制字节、临时与驻留内存、R=1/9/100 | 不达成本边界则不默认转换 |

把调 OMP_WAIT_POLICY、编译选项、线程绑定作为独立控制变量，两边一起改变，不列作仅新内核的算法收益。完整构建 flags 与每个相关内核的反汇编必须保存。

## 2. 正确性先于大矩阵计时

继承 v1 的 850 项核心检查、类型回退和全量输出验证，再增加：

- **固定行长路径**：全部为 8、仅第一个 / 中间 / 最后一个行不是 8、行数小于分组数、不整除分组数、零行 / 零列；拒绝把抽样判断当作完整结构证明。
- **预取边界**：D 大于行长、D 大于线程区间、最后一个非零元、空区间、非法列号、INT64 偏移边界；地址表达式在求值前合法，不依赖 prefetch 指令不抛异常来掩盖越界读取。
- **分区覆盖**：T>m、全空行、均匀行、集中 / 分散长尾；每行被覆盖一次，不漏不重；m+nnz、目标乘法 / 加法溢出；实际 T 改变的重新绑定。
- **merge 拼接**：一个巨行跨 2/12/24 个线程；两个相邻巨行；线程起止在同一行；边界正好在行端；连续相同行偏移对应的大量空行；0 nnz；所有片段每轮清空；片段合并后只加旧 y 一次。
- **通用语义**：非零 y，逐次变化 x，R=0/1/3，多次调用；-0、NaN/Inf、强消去、subnormal、重复坐标和显式零。不能将 R 次加法替换为一次乘 R；不能跳过空行时悄悄改变严格 y+=0 行为。
- **计划失效**：数值、结构、源向量与线程数变化；原 CSR 不复制时应读取新值，SELL 快照必须刷新。未建立版本管理时测试显式失效接口。
- **资源 / 类型**：O(T) scratch 每处分配失败、一致回退、超预算、unsupported ISA / f64 / 混合精度 / 整数 / 复数；不真的分配数十 GB 制造 OOM。

有限值采用 long double 与随行长 / Σ|a*x| 制定的误差界；同时保存绝对误差和相对误差，强消去时不只看相对误差。保持行顺序的路径在双方匹配 -ffp-contract=off 的专门对照中检查逐位结果；NaN 用分类等明确规则。merge / 横向归约不承诺逐位一致，严格模式不启用。全局不加 fast-math。

测试配置包含 1/12/24 线程，ASan/UBSan、实际 native 构建、portable 编译与失败注入。数值测试与性能测量分开，不将 sanitizer 程序用于计时。

## 3. 实验规模与保留集

先做小测试，再中等规模消融，通过者才进入超大矩阵；不在每次修改后重跑无意义的全参数笛卡尔积。

1. 复用 v1 的 22 类中等输入与原超大矩阵，校验原 SHA；它们已用于提出 v2，不算独立验证集。
2. 冻结内核 / 规则后，使用不同 seed、不同尺寸及行数尾部的保留集。随机列增加真正的整行均匀抽样并排序，避免只验证“每列区间一项”的原生成结构；增加不同长尾比例、两个巨行和空行成簇 / 均匀两种分布。
3. 增加至少两个真实 Matrix Market 输入，覆盖有局部结构和不规则行分布。下载前记录作者 / 集合、版本 / 许可、SHA、field 与 symmetry；对称展开和 pattern 转换说明真实 nnz，不能将半矩阵当完整 SpMV。具体数据尚未在本轮下载或测量。

主条件用 1/12/24 线程、R=1/9/100；2/4/8 线程仅用于已通过者的扩展曲线。小输入增加内部 R 降低计时量化，但不能把不同 R 混作同一比较。分开报告请求 / 实际线程数、首次调用和稳态结果。

## 4. 采样、时间与模型边界

- 中等规模初筛至少 5 个独立进程；主大矩阵及含糊条件至少 10 组相邻随机 AB/BA 配对，固定随机种子。保存所有样本，不按“看起来慢”删除。
- 工程对照保留原始计时含并行进入 / 退出和逐次屏障；新版本单列全部 P 和清理。若把验证合并到构造，报告对应构造阶段和全程 wall，不能通过移动代码到计时区间外隐藏新增工作。
- 同进程诊断若测稳态，双方统一预热、重置各自 y，平衡顺序；不把它与无额外预热的独立进程结果拼成一张“加速表”。首次调用也不等于整个 DRAM 已冷。
- 自动选择的收益按实际所选路径评估，试算 / 恢复 / scratch 都付费；事后最优仅作上限对照。规则选择集与验证集分开。
- 配对重采样以进程对为单位，给出加速比的区间与中位数；不是把同一进程里的 R 次循环当 R 个独立样本。10 组也不保证足以识别所有小差异，区间宽就增加样本或保留不确定性。
- 记录 WSL、宿主活动可知信息、实际放置、编译器与二进制 SHA。不可控制的频率 / 调度如实写明，不承诺完全无噪声。

## 5. 最终报告与准入

每个输入保留 original、v1、最强匹配 CSR 和实际 v2；列出 P、execute、清理、P+execute、进程 wall、RSS、额外驻留 / 临时字节、误差和回退原因。按输入列正收益、退化、不确定、回退；不只算挑选胜者后的几何平均。

主目标检查超大均匀 R=9 相对原始最佳线程配置；次目标分别检查小矩阵、集中长尾、巨行，不能互相替代。拟采用至少 5% 的中位总成本改善且配对区间支持收益作为工程准入，不把阈值或统计区间当跨机器保证。

若只有巨行变快而均匀矩阵没变快，报告“巨行适用的 v2”，该均匀输入仍用原始。全部新内核正确并不意味着性能验收通过。
