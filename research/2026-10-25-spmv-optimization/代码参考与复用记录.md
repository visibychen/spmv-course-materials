# 源码参考、适配和复用记录

核查日期：2026-10-25。此次没有把第三方内核复制进核心仓库，也没有声称这些代码可以未经适配直接编译成 f32 替代实现。下面的行号对应固定版本；文件哈希和固定链接见 `code-sources.json`。

## 1. GHOST：跨行 SIMD 的具体模板

- 仓库：[RRZE-HPC/GHOST](https://github.com/RRZE-HPC/GHOST)，commit `22a004dbbfb604d7b04b0bde813c8100d403cfcc`。
- [plain 模板](https://github.com/RRZE-HPC/GHOST/blob/22a004dbbfb604d7b04b0bde813c8100d403cfcc/src/autogen/sell_spmv_plain.c.in)：chunk 循环、`offs + j*CHUNKHEIGHT + r` 的列优先 slice 布局、每行独立累加。
- [AVX2 模板](https://github.com/RRZE-HPC/GHOST/blob/22a004dbbfb604d7b04b0bde813c8100d403cfcc/src/autogen/sell_spmv_avx2.c.in#L76-L110)：按 chunk 分配线程，载入相邻多行数值，收集对应 x，用向量寄存器保持独立行和，最后写 y。
- 已读部分函数是 double AVX2，而本项目主要 baseline 是 f32；单精度需要对应的 lane 数、intrinsics 和尾部处理。
- 文件含 `#GHOST_SUBST` / `#GHOST_UNROLL` 生成器标记，不是可直接复制编译的普通 C 文件。GHOST 还依赖自身结构体、运行时、置换与对齐管理。
- 不建议选用名字含 `UNROLLEDDOESNOTWORK` 的旧 AVX 模板作为移植起点。
- 许可：固定版本 `LICENSE.md` 为 BSD-3-Clause 文本。

**计划复用**：方法与数据布局，优先用普通 C 写清楚 f32 的 slice 循环，再验证编译结果；若实际改编模板，记录源文件、commit 和修改范围，保留相应版权、许可与声明。保持 y 累加语义，不照搬覆盖写或 non-temporal store 分支。

## 2. AMD AOCL：保持 CSR 的收集 / 归约策略

- 仓库：[amd/aocl-sparse](https://github.com/amd/aocl-sparse)，commit `d633b58d3cfa266a2a0a8e2fb0f22cc97ee7355c`（AOCL 5.3.2 相关提交）。
- [csrmv_kt，第 56–91 行](https://github.com/amd/aocl-sparse/blob/d633b58d3cfa266a2a0a8e2fb0f22cc97ee7355c/library/src/level2/aoclsparse_csrmv_kt.cpp#L56-L91)：向量块循环、余数处理、横向归约、alpha / beta 的写回分支。当前接口需要取 alpha=1、beta=1。
- [AVX2 kt_set_p，第 84–97 行](https://github.com/amd/aocl-sparse/blob/d633b58d3cfa266a2a0a8e2fb0f22cc97ee7355c/library/src/include/kernel-templates/kt_l0_avx2.hpp#L84-L97)：float 使用 `_mm256_set_ps` 从各列位置构造向量。这是“对比硬件 gather 与手动收集”的具体代码依据；最终生成的指令仍需反汇编确认。
- [analysis，第 35–49 行](https://github.com/amd/aocl-sparse/blob/d633b58d3cfa266a2a0a8e2fb0f22cc97ee7355c/library/src/analysis/aoclsparse_analysis.cpp#L35-L49)：该 `aoclsparse_optimize_mv` 路径对非 double、非 CSR、尺寸 <=1 的输入提前返回。**这不等于 AOCL 不支持 f32 SpMV**，只说明不能声称这个特定格式优化路径会处理 f32。
- 接口的 `aoclsparse_int` 宽度与本项目 `int64_t row_ptr` 不能直接假定相同；接入厂商库要明确 LP64 / ILP64 和范围检查。
- 许可：`LICENSE.md` 的 AMD 代码为 MIT，具体文件头亦有许可；仓库同时提示需核查逐文件版权。

**计划复用**：只抽取适合本项目的 f32 收集和尾部组织，先作为显式实验内核。不引入 AOCL 整套依赖，也不把调用外部库包装成本人的算法。显式横向归约 / FMA 可能改变浮点结果，应按精度模式验证。

## 3. merge-spmv：CPU 的超长行分解

- 仓库：[dumerrill/merge-spmv](https://github.com/dumerrill/merge-spmv)，commit `18895571ce9af960ee207dae541b0ffc701ea4bb`。
- [cpu_spmv.cpp，第 211–250 行](https://github.com/dumerrill/merge-spmv/blob/18895571ce9af960ee207dae541b0ffc701ea4bb/cpu_spmv.cpp#L211-L250)：`MergePathSearch`。
- [第 292–352 行](https://github.com/dumerrill/merge-spmv/blob/18895571ce9af960ee207dae541b0ffc701ea4bb/cpu_spmv.cpp#L292-L352)：`OmpMergeCsrmv`，按 `num_rows + num_nonzeros` 划分、计算整行与部分行，再处理 carry。
- 原实现是 `y=Ax`：第 332 行覆盖写 y。当前项目是 `y+=Ax`，适配时必须在最终合并后对每行累加一次，不能让每个片段重复加上旧 y。
- 临时数组固定为 256 个元素，路径坐标 `int2` 和部分对角线变量为 int。移植需要按实际线程数分配 scratch，并检查 / 改为适当的 64 位计数，不能仅把模板 OffsetT 改成 int64 就认为所有溢出已解决。
- 整个 benchmark 包含 MKL 和旧平台构建依赖。核心分解与 MKL 对照框架可以分开研究，不要求把整套工程搬进当前 C 项目。
- 许可：`LICENSE.TXT` 为 NVIDIA 的三条款 BSD 文本。

**计划复用**：后续巨行 / 大量空行的算法与边界修正逻辑；初期保留原始函数作为普通行的回退。必须测试一行跨多个线程的合并、空行边界、m+nnz 溢出及重复调用。

## 4. CSR5：有作者实现，但不作为首个移植目标

- 仓库：[作者实现](https://github.com/weifengliu-ssslab/Benchmark_SpMV_using_CSR5)，commit `4b06ce35e45c3c61a51e249e12e1c4954af443fa`。
- 重点文件：`CSR5_avx2/anonymouslib_avx2.h`、`detail/avx2/csr5_spmv_avx2.h`、`format_avx2.h`。
- AVX2 Makefile 默认 `VALUE_TYPE=double`；内核中大量 `__m256d`。不是改成 float 就自然得到正确的单精度实现。
- `main.cpp:63` 预热清零使用 `sizeof(double)*m`；若仅替换 VALUE_TYPE 为 float，必须先审计这类写入长度，不能照着运行。
- 示例 CSR row_ptr / col_idx 使用 int，与本项目 64 位 row_ptr 不同；描述符还涉及位标记和有效位宽。
- 仓库根 `LICENSE` 为 MIT；AVX-512 目录的原目标包含 Knights Landing，不等同于当前 Ryzen 的已验证优化。

**计划复用**：分段归约与 tile 的研究参考、后续 f64 外部对照。完整 f32 / 64 位偏移适配暂不作为 v1 核心工作。

## 5. 当前项目作者自己的软件归档

来源：[Zenodo 7837264，版本 1.0.0](https://zenodo.org/records/7837264)。两份 ZIP 已按页面 MD5 验证，并记录 SHA-256。

### spmv-1.5.zip

内部目录为 `ellspmv-1.5/`，包含 `csrspmv.c`、`ellspmv.c`、README 和 COPYING。

- `csrspmv.c:1120–1149`：double CSR，含外层 `omp for simd`。
- `csrspmv.c:1187–1234`：`csrgemvrp`，显式线程行区间。
- `csrspmv.c:1237–1316`：`csrgemvnz`，按非零元划分和边界原子更新。第 1265 行对部分 y 写零，因此不能把这个函数视为当前累加接口的无条件替换品；需重新设计 scratch 和统一写回。
- `ellspmv.c:955–1059`：行优先 ELL、固定 16 项展开和外层 SIMD。**这是 ELLPACK，不是 GHOST 的列优先分片 SELL。**
- README 的 AVX-512 示例使用 `-ffast-math -mprefer-vector-width=512`，内核为 double、计时按轮输出；这些条件与当前 f32 baseline 不同。不能直接拿示例 GFLOP/s 对比本机。
- 文件头注明 GPL-3.0-or-later；有额外作者 / 历史记录，移植时按原文件保留。

### Libmtx 0.4.0

- `src/mtxreorder.c:121–167` 的帮助说明确认：`--ordering=rcm|metis|nd|custom`、`--parts`、行列置换及逆置换输出。
- `configure.ac:169–178` 检测 METIS；未找到时会构建不带 METIS 的版本，不能假设安装完 Libmtx 就能运行 METIS 模式。
- 用于后续真实矩阵的作者方法复现；先确认置换方向，再验证 `A'=P A Q^T`、`x'=Qx`、`y=P^T y'`。
- COPYING 为 GPLv3 文本；逐文件许可在真正复用时保留和核对。
