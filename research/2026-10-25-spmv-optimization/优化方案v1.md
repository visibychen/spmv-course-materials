# 优化方案 v1：CSR 多内核与可选 SELL-C-σ 后端

版本日期：2026-10-25。状态：**有来源支撑的设计，待实现与验证**。核心原始版本 `9352c865044f4c8b344d6fe5a277200a89f7a08b`。引用编号与固定代码见 [资料索引](资料索引.md)、[复用记录](代码参考与复用记录.md)。

## 1. 建议采用的路线与范围

首轮目标是：**针对当前均匀短行矩阵，比较原始 CSR、标量 CSR、AOCL 风格收集策略和无排序 SELL-C；保留原始路径作为完整功能回退。**

主要算法依据是 SELL-C-σ [P1, C1]；保持 CSR 的内核依据是 AMD AOCL [C2]；不均衡扩展依据是原作者归档和 merge-based CPU 实现 [P3, P6, C3]。这些来源提供可以直接参考 / 改编的方法，不自创一种未经验证的新格式。

第一轮只优化 **f32 矩阵、f32 输入、f32 输出、非转置 SpMV**。double、混合精度、整数、复数先走原始分派。所有路径维持当前 `y ← y + Ax`，保持输入 / 输出维度检查与错误处理。

SELL 是 CSR 派生的可选执行表示，CSR 仍是规范输入与回退存储。如果后续课程限定纯 CSR，可以单独交付第一阶段与工作量分区；SELL 阶段不影响纯 CSR 路线成立。

## 2. 阶段 A：建立更强的 CSR 对照，缩小改动

### A1. 显式保留原始内核

- 原始文件和 baseline 历史结果不改写。
- 新分支中保留可显式选择的原始内核，原程序的编译选项、数值类型和线程环境仍可完整复现。
- 补测原始 novec 的 24 线程条件；现有只测 1/12 线程，不能据此推导 24 线程结果。

### A2. 局部标量内核

用独立编译单元控制其自动向量化选项，使关闭向量化的影响限于被比较的 f32 SpMV 内核。既有实验关闭的是整个构建的循环 / SLP 向量化；新实验需要确认局部控制是否仍取得相同趋势。

它作为强对照和潜在短行回退，不作为“发明新的 CSR 算法”。变更原因来自本机已测的 1/12 线程对照和 GCC 选项语义 [D1]。

### A3. AOCL 风格内核原型

参考 `kt_set_p` 的逐元素取 x / 组装向量与 `csrmv_kt` 的块循环和尾部结构 [C2]，比较：

1. 原始编译器 gather 方案。
2. 手动收集向量的方案。
3. 标量方案。

先保持 CSR 数组和线程划分不变，控制变量只落在计算组织上。最终汇编必须核实收集方式；不能只看到 `_mm256_set_ps` 就断言机器码没有 gather。

原厂向量内核的横向归约、FMA 与当前加法链不必逐位一致，因此要明确数值模式；不能靠全项目加 `-ffast-math` 同时改变读取、异常值处理和所有类型的计算规则。

**阶段 A 的价值**：获得可靠的强基线，防止 SELL 的加速仅仅来自修正了一个本来就更慢的编译选择，也提供范围小、便于上游评审的实现切口。

## 3. 阶段 B：主要算法候选——跨行 SELL-C-σ

### B1. 初次只做无排序 C=8 / 16

当前每行 8 项、总行数同时可被 8 和 16 整除，因此这两个配置的数据槽填充倍率均为 1。C 是同时处理的行数，**不是固定每行恰好有 C 项**。

初试参数由本机 f32 的 256 / 512 位可用通道数启发，属于待测参数，不沿用 GPU 的 32/64 行默认，也不由“512 更宽”推断更快。σ=1 采用 P1 的“不排序”约定，输出行顺序不变。

### B2. 数据布局与独立累加

对每个 slice s，记录：

- `slice_ptr[s]`：64 位槽偏移。
- `slice_width[s]`：本 slice 最大行长，保存和计算时检查范围。
- 列优先 `values` / `column_indices`：同一位置 k 的 C 行连续排列。
- 不等长输入所需的行长 / lane 有效信息；必要时的 `row_map`。均匀、无排序场景可用隐式映射和已验证统一行长省去这些数组。

计算语义示意（不是已经实现的代码）：

```text
为 slice 中每个有效行设置独立累加器 sum[lane] = 0
按该行原 CSR 项序逐步处理 k：
    对 k < row_length[lane] 的通道收集 x、乘法并累加
所有项完成后：
    y[original_row(lane)] += sum[lane]
```

每条 lane 对应不同 y，避免同一行在多个 lane 之间横向归约 [P1, C1]。仍然需要访问 x；不会消除随机访问，也不承诺达到持续内存带宽。

注意累加器要从零开始，最后再加旧 y；直接把 y 装进累加器再逐项相加，会改变当前内核“先求一行和、再加 y”的浮点顺序。

### B3. 泛化到不等长行

仅当 B1 有收益，才增加局部排序 σ∈{128,1024} 的有限对照；这是本项目搜索范围，不是文献给出的本机最优值。局部排序在 padding 和 x 访问局部性之间取舍 [P1]。

本项目的普通 SpMV 后端可以仅对行做置换：若 A'=P A，则 x 不变，以 `row_map` 将结果加回原始 y。若另外复现行列重排，则使用独立 Q：A'=P A Q^T，x'=Qx，结果回到 y=P^T y'。

无排序时写回连续 y；有排序时，每次 SpMV 的原行序写回 / 恢复都计入内核成本。不要只在最后一次恢复结果，却把这种特例收益当作通用逐次调用接口的性能。

### B4. 转换前的拒绝条件

检查 `slots = Σ C×max_row_length_in_slice`、填充率、实际字节数与峰值；原 CSR、派生数组、置换、输入输出、scratch 都计入。使用运行时可用内存和明确的用户预算，而非写死“本机永远还有 13 GiB”。

如果出现下列情况，先保留原路径：

- 转换会溢出或无法分配；长尾使 padding 代价不可接受。
- 调用次数太少，预处理不能回本。
- 未适配的数值类型 / ISA / 数值要求。
- 实测没有稳定优势。

是否用某个填充倍率作为自动阈值，须由独立训练矩阵或明确策略决定，v1 不把 1.2、2.0 之类数字伪装成论文通用定理。第一轮显式指定候选，暂不自动分派。

## 4. 阶段 C：不规则输入的工作量划分

### C1. 连续行工作量划分

参考 P6 的显式行区间接口，先在 CSR 上复现按行工作量选择线程边界，保持一行由一个线程负责。统计每线程 nnz / 行数，比较原始划分、工作量划分、dynamic / guided 对照。

在大量空行场景，可用 `work_prefix[i] = row_ptr[i] + λ·i` 作为候选成本近似，λ=1 从 P3 同时计行边界和 nnz 的思想出发。**该加权整行切分是本项目近似，不是完整 merge-path，也没有证明 λ=1 对所有 CPU 最优。** 当前均匀行输入会给出与等行划分相近的边界，预计不带来主要收益。

### C2. 单条巨行 / 大量空行扩展

如果 C1 暴露一条行的工作量已经超过理想每线程工作量，整行划分与 dynamic 无法消除此下界。此时参考 `OmpMergeCsrmv` [C3] 适配 merge-based。

- row_ptr 保留 int64，坐标、对角线、m+nnz 与乘法表达式一并审计。
- scratch 按实际团队大小分配，不照搬作者示例的固定 256。
- 对跨线程的同一行先形成独立部分和，在同步后合并，**最终只加旧 y 一次**。
- 空行与零 nnz 特判；每轮都完成 carry 修正，不能随便添加 nowait。
- 拆分长行改变求和结合顺序，数值模式与参考需明确。

这个阶段是对不规则矩阵的扩展，不要求它在当前均匀短行矩阵上胜出；常规情况可继续用更简单的内核。

## 5. 暂不进入首轮实现的分支

- **重排**：优先复现原作者 P5/P6 的 Libmtx `mtxreorder`、RCM 与 METIS 流程，针对有结构真实矩阵；依赖、置换、预处理都记录。当前随机矩阵不预设获益。
- **缓存分块 / BSR**：先有 x/y 驻留或稠密小块的结构证据 [P4]。当前极低密度随机矩阵不是盲目转换的理由。
- **CSR5**：方法有依据，但现成 CPU 实现的 double / 索引 / 描述符适配较多，放在后续对照。
- **预取 / 去屏障**：在主内核结果稳定后单独消融。去屏障仅对固定 x、独占 y、固定任务所有权成立，不能推广到每轮 x←y 的迭代求解器。[D3, D4]

## 6. 工程接口草案与实现拆分

以下文件和选项是未来设计，不表示仓库中已经存在：

```text
read matrix → 原 CSR → inspect/prepare → execute(R 次) → 原行序结果 → free
```

- `spmv_plan.[ch]`：元数据、选择结果、线程配置、内存和生命周期。
- `spmv_csr_scalar.c`：局部编译控制的标量对照。
- `spmv_csr_pack.c`：AOCL 风格收集原型。
- `spmv_sell.[ch]`：派生布局和跨行内核。
- 后续 `spmv_merge.c`：不规则扩展。
- `main.c`：读取和创建 CSR 后准备计划；保留原始计时，并另报 prepare / execute / total；避免重复分派、分配 scratch 落入每轮热循环。
- 初期命令行建议显式 `--kernel=original|csr-scalar|csr-pack|sell` 与 `--sell-chunk=8|16`；`merge` 和自动模式放到阶段 C 后。正式实现时补充参数解析、帮助、错误路径与测试。

准备一次、执行多次是矩阵结构复用，**不是缓存 Ax 结果**。x 变化仍完整计算；矩阵数值 / 结构改变要刷新派生值或使计划失效。实际团队数与计划匹配后，线程一致地进入同一后端，避免在部分线程中回退导致死锁。

建议拆成独立变更：正确性与基准协议 → CSR 对照 → 无排序 SELL → 不等长 / 成本控制 → 工作量划分 → 可选 merge。每个变更都有单独来源、测试和实验记录，方便日后上游评审。

## 7. 成本模型：必须同时报告内核和端到端

在共同的 CSR 已准备好之后，令：

```text
T0：原始或强 CSR 对照的单次 SpMV 时间
T1：新后端单次 SpMV 时间（包含每次结果恢复 / 合并）
P ：inspect + 调参 + 格式转换 + 一次性映射 / scratch 准备
R ：真实调用次数
原始总时间 = R*T0
新方案总时间 = P + R*T1
```

只有 T1<T0 且 R>P/(T0−T1)，新方案才在此范围内端到端占优；严格更快的最小整数次数为 `floor(P/(T0−T1))+1`。若每次都有额外向量置换，必须计入 T1，不能只算一次。这个分析框架与 CSR5 的迭代成本讨论一致 [P2]。

另外保留“文件读取 + CSR 创建 + prepare + R 次执行 + 输出”的全过程时间，以区分内核研究和最终使用体验。既有约 9–10 s 的文件解析与约 0.1 s 的并行内核并非同一计时范围。

当前 R=9 的实验不能自动作为新格式受益场景；P、T1 均未实测，因此没有承诺回本次数。调参本身要计入 P，不能无限测试候选，再只呈现最优内核。

## 8. 数值和兼容性要求

- 默认不启用全局 fast-math；保留原始路径。显式向量归约 / FMA 的模式要披露可能的数值差异 [D1]。
- 需要逐位行为时，采用原始回退或双方匹配 `-ffp-contract=off` 等数值选项后验证；不能与历史默认 FMA 配置混称完全相同。
- SELL padding 和无效 lane 必须掩蔽，不能越界访问或引入 0×NaN/Inf；有 NaN/Inf 的有效项遵循选定接口语义。
- 明确初始 y、重复累加、原 CSR 项顺序；强消去 / 长行用宽精度参考和随精度 / 行长制定的判据。
- 检查零尺寸、零 nnz、非法索引、对称展开、m≠n、m<C、偏移溢出与资源失败。完整清单见 [极端情况](极端情况与验证矩阵.md)。

## 9. 实验与验收

### 第一轮实验组合

| 组别 | 实现 | 作用 |
| --- | --- | --- |
| B0 | 原始 CSR、默认自动向量化 | 保留历史基线，并在新实验同协议重测 |
| B1 | 原始 / 局部标量 CSR | 强对照，补 24 线程与更广矩阵 |
| B2 | AOCL 风格收集 CSR | 判断取 x / 归约组织是否值得继续 |
| S8 / S16 | 无排序 SELL，C=8 /16 | 主要布局候选，区分 C 的影响 |

先小矩阵正确性和中等规模初筛，再把通过者放到当前超大矩阵及独立结构矩阵上。至少 5 个独立进程样本，固定随机测试顺序、线程位置和编译 / 浮点条件；若差异与波动相近，增加样本再决定。

新实验若采用预热，所有对照采用相同预热；若保持历史“不插入预热”的口径，新内核也保持相同条件。保留历史结果，另建实验目录，不用更热的缓存或不同的计时范围制造提升。

### 每项必须保留的输出

- 正确性与错误 / 资源退出行为。
- 源码 commit、编译器、选项、诊断与实际内核汇编。
- 矩阵来源 / 版本 / 许可 / SHA、类型、真实 nnz、行分布、padding、线程工作量。
- prepare、execute、全程 wall time、峰值 RSS；逐次 CSV 与汇总中位数 / 极差。
- 同线程对比，以及原始和优化各自最佳线程配置的工程对比。
- 每个矩阵单列的收益 / 退化 / 回退原因，不能只报告胜出的输入；测试集汇总同时保留逐矩阵数据。

### 通过条件与停止条件

1. 正确性和边界测试通过，保留全部原功能的可用回退。
2. 相对 B0 与最强匹配 CSR 对照都说明收益；若只优于 B0 而不如 B1/B2，明确呈现，不能把“换编译策略”混成布局收益。
3. 内核优势高于本次波动，并按目标 R 核算端到端。失败或负收益同样记录，候选可以不进入默认路径。
4. 对不合适的输入有明确处理；回退策略本身的 inspect / 分派成本也要计入，不能宣称回退后必然零损失。
5. 没有持续带宽与实际流量证据前，Roofline 只做有标记的模型 / 上限分析。STREAM 等顺序带宽不能当作随机 gather 一定应达到的吞吐 [P8, D8]。

## 10. 当前可作出的决定

可以开始实现“原始路径保留 + 局部 CSR 对照 + 无排序 SELL8/16”，依据、参考代码、已知风险与验证方法均已具备。暂不预选最终最快内核、不承诺加速倍数；先通过第一轮数据决定是否继续排序、merge 和真实矩阵重排。
